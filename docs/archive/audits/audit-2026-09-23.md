# Audit Report - 2026-09-23

## Audit Update 14:24

### 1. Mixed Language / Untranslated German Fragments in English Feed

**Affected Component**
- `docs/feed.en.xml` (Translation pipeline / `src/build_feed.py`)
- Source: `cache/wl_9d709a/events.json`

**Display Issue Description**
The English feed contains several items with untranslated German fragments, resulting in clumsy, mixed-language phrasing.
- In the `N31` disruption, the title is "N31: Stammersdorf replacementless Discontinued", and the description contains "Ersatzlos Discontinued" and "Ab 30. September …".
- In the `64A` and `72A` disruptions, the descriptions contain "etwa 20 Meter in Richtung …" and "Ab 22. September …" which are left entirely untranslated.
This is likely due to the NMT model failing to process these prefixes or fragments properly without glossary mapping.

**Proposed Solution**
Update the translation glossary (`_apply_domain_glossary`) and preprocessing logic in `src/build_feed.py` to explicitly map these common German transit prefixes and fragments (e.g., "Ersatzlos", "Ab", "etwa 20 Meter in Richtung") to their English equivalents before NMT translation.

### 2. UI Inconsistency - "Minuten" instead of "min" in Markdown Stats

**Affected Component**
- `scripts/generate_markdown_stats.py`
- `docs/statistik.md`

**Display Issue Description**
The generated Markdown statistics headers `### Verspätungen ⌀ Minuten je Wochentag` and `### Verspätungen ⌀ Minuten je Stunde` use the unabbreviated word "Minuten". This violates the project-wide UI consistency guideline (established in previous audits and memory) that delay durations should always use the abbreviation "min" to maintain visual harmony with the frontend (`docs/assets/site.js`) and other headers (like "Verspätungen > 9 min").

**Proposed Solution**
Modify `scripts/generate_markdown_stats.py` to use "min" instead of "Minuten" in these specific Markdown headers (e.g., `### Verspätungen ⌀ min je Wochentag`).

### 3. Awkward Truncation of Long Disruption Descriptions

**Affected Component**
- `docs/feed.xml` and `docs/feed.en.xml`
- `src/providers/baustellen.py` (Title sanitation)

**Display Issue Description**
The title for the U4 disruption is awkwardly truncated mid-word in both feeds. In the German feed, it reads "U4: Vordere Zollamtsstraße von Marxergasse und Kleine Marxerbrücke bis Unbenannte Verkehrsfläche und Rad…". This truncation cuts off the word "Radweg" (or similar). In the English feed, this directly translates to "...unnamed traffic area and wheel…", which makes the awkward truncation even more prominent and confusing for users.

**Proposed Solution**
Refine the truncation logic (e.g., `tidy_title` in `src/providers/baustellen.py` or text utility functions) to ensure strings are truncated cleanly at word boundaries before appending the ellipsis, rather than cutting off at a strict character limit mid-word.
