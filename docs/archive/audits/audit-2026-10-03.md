# Daily Audit - 2026-10-03

## Audit Update 16:30

### Affected Component
Source Data Sanitization (Baustellen) -> `src/utils/text.py` (`_GLUED_WORD_RE`)

### Display Issue Description
The raw JSON payload from the OGD City of Vienna for Baustellen contains glued words that lack spaces. The current regex spacing sanitization `_GLUED_WORD_RE` handles many cases but misses standard German articles like "Der", "Die", and "Das", resulting in poorly concatenated texts like "DerFußgängerverkehr" and "DieArbeiten" bleeding into the feed descriptions.

### Proposed Solution
Update the `_GLUED_WORD_RE` regex to include length-3 articles (`Der`, `Die`, `Das`) in its lookbehind assertions, separated appropriately from the length-2 lookbehinds, allowing it to correctly insert a space when these glued patterns are encountered.

---

### Affected Component
Feed Formatting (Wiener Linien) -> `src/providers/wl_text.py` (`_AB_DATE_RE`)

### Display Issue Description
The English and German feeds contain redundant date strings in the titles when the date is prefixed with "am" (e.g., `46/47A/47B: Veranstaltung am 04.10.2026`). Currently, the `_AB_DATE_RE` regex only strips redundant dates starting with "ab", leaving "am" dates in the feed titles unnecessarily.

### Proposed Solution
Modify `_AB_DATE_RE` to match `(?:ab|am)` instead of just `ab`, ensuring that dates starting with both "ab" and "am" are successfully stripped from the feed titles for cleaner display.

### Affected Component
English Feed Translation -> `src/build_feed.py` (`_GLOSSARY_BASE`)

### Display Issue Description
The English feed (`docs/feed.en.xml`) contains clumsy and literal translations of transit verbs, such as translating "Züge halten" (Trains stop) as "Trains keep" (e.g., "Trains keep in loop, Wipplingerstr 39" for line D). This is caused by the MarianMT model mistranslating the transit idiom.

### Proposed Solution
Add the specific transit verbs "Züge halten" (mapped to "Trains stop at") and "Busse halten" (mapped to "Buses stop at") to the `_GLOSSARY_BASE` in `src/build_feed.py` to ensure they are masked with `XGLO` placeholders and correctly idiomatically translated before being passed to the NMT model.

### Affected Component
English Translation & Masking -> `src/build_feed.py` (`_STREET_SUFFIX_CORE`)

### Display Issue Description
In `src/build_feed.py`, transit vocabulary like "Einstieg", "Ausstieg", "Umstieg", and "Zustieg" might get caught by the `_STREET_SUFFIX_CORE` regex because they end in "stieg". "Einstieg" is protected by `_GLOSSARY_BASE` now, but others could still be erroneously masked as street suffixes and remain German.

### Proposed Solution
Use negative lookbehinds in `_STREET_SUFFIX_CORE` to prevent it from matching valid transit nouns that end in "stieg" or "steig", such as `(?<![Ee]in)(?<![Aa]us)(?<![Uu]m)(?<![Zz]u)`. Note that "Einstieg" etc. might not be translated correctly if caught. Or better yet, ensure all such words are mapped in the domain glossary.
