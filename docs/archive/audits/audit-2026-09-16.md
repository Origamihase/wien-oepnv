# Audit: Daily Diagnostic Report

**Datum:** 2026-09-16

## Audit Update 16:30

### Affected Component
`src/providers/baustellen.py` (Title Processing) and `scripts/update_baustellen_cache.py`

### Display Issue Description
The Baustellen feed (Stadt Wien OGD) outputs highly verbose titles that contain redundant filler words and extraneous location details, which clash with the concise nature of the transit feed. Examples found in the cache include `Märzstraße 49 bis Kreuzung Huglgasse sowie Kreuzung Huglgasse bis Kreuzung Hütteldorfer Straße`. The titles are not being processed by a `tidy_title` sanitization function to strip words like "Kreuzung" and trailing addenda.

### Proposed Solution
Implement a `tidy_title` regex sanitization function in `src/providers/baustellen.py` that strips redundant words (e.g., `\bKreuzung\s+`) and trailing specific location additions (e.g., `, auf Seite...` or `, Höhe...`), compresses multiple spaces, and strips leading/trailing whitespace. Hook this into the title extraction logic in `scripts/update_baustellen_cache.py`.

### Affected Component
`src/providers/baustellen.py` (Description Parsing)

### Display Issue Description
The raw descriptions for Baustellen (construction sites) originating from the City of Vienna OGD payload contain awkwardly concatenated sentences and compound words lacking spaces. Examples found in the live cache include "DerFußgängerverkehr", "NähereInformationen", "DieArbeiten", and "Außerhalbder". This lack of spacing sanitization leads to unprofessional and difficult-to-read text in the German feed (and downstream translations).

### Proposed Solution
Add a text sanitization pass in `src/providers/baustellen.py` (e.g., using regex `re.sub(r'([a-zäöüß])([A-ZÄÖÜ])', r'\1 \2', text)`) during the description extraction to detect and insert spaces between improperly concatenated words.

### Affected Component
`src/build_feed.py` (Translation Pipeline & Domain Glossary)

### Display Issue Description
In the English feed (`docs/feed.en.xml`), the noun "Wollzeile" is literally translated by the ML model to "wool line" (e.g., "water pipe fracture in the area of wool line"). Additionally, the glossary mapping generates awkward grammar, such as "an service obstruction", where the English article "an" clashes with the noun phrase because the underlying German term maps to a phrase starting with a consonant sound.

### Proposed Solution
1. Update `_STREET_SUFFIX_RE` or the entity masker in `src/build_feed.py` to ensure "Wollzeile" (and similar locations ending in "-zeile") is shielded from translation by treating it as a proper noun suffix.
2. Update the `_GLOSSARY_BASE` mapping for disruptions to use a phonetically appropriate starting word (e.g., map to "obstruction" instead of "service obstruction") to prevent grammar mismatches with the NMT generated articles.
