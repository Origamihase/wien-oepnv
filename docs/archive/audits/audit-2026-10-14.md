## Audit Update 15:11

### Affected Component
`src/build_feed.py`, `docs/feed.xml`, `docs/feed.en.xml`

### Display Issue Description
**Awkward Truncation:** In the live RSS feeds (`docs/feed.xml`, `docs/feed.en.xml`), the description for the disruption on lines `30A/31A/36A/36B` is awkwardly truncated: `... 31A in Richtung Jochbergengasse, 36A und 36B …`. This is caused by the `_truncate_summary_180` logic in `src/build_feed.py`, which strictly limits the summary to 180 characters. By doing so, it drops critical re-routing and relocation information for the lines mentioned at the end of the sentence or in subsequent sentences.

### Proposed Solution
Modify the truncation logic (`_truncate_summary_180` or `_last_sentence_end`) in `src/build_feed.py` so it does not arbitrarily cut off within lists of affected lines, or implement an exception for stop relocations affecting multiple lines to ensure all critical re-routing information is preserved.

### Affected Component
`docs/statistik.md`, `scripts/generate_markdown_stats.py`, `docs/assets/site.js`, `docs/site.html`

### Display Issue Description
**Hardcoded Wording Inconsistency:** In the generated Markdown statistics (`docs/statistik.md` and `README.md`) and the generator script (`scripts/generate_markdown_stats.py`), there are hardcoded uses of the word `Minuten` for delay durations (e.g., `### Verspätungen ⌀ Minuten je Wochentag`, `### Verspätungen ⌀ Minuten je Stunde`). Additionally, `docs/assets/site.js` and `docs/site.html` contain comments and strings referring to `Minuten` (e.g., `// 5 Minuten`). This violates the project's visual harmony guideline to consistently use the abbreviation `min` for all delay durations.

### Proposed Solution
Update `scripts/generate_markdown_stats.py` to replace `Minuten` with `min` in table headers. Also update `docs/assets/site.js` and `docs/site.html` strings/comments to consistently use `min`.
