## Audit Update 16:30

### 1. Missing Spaces in Concatenation
**Affected Component:** Upstream Data / `src/providers/baustellen.py` (Missing spacing sanitization)
**Display Issue Description:** In the cache payload (`cache/baustellen_d438c3/events.json`) and the resulting feeds, sentences and compound words are awkwardly concatenated without spaces (e.g., `DerFußgängerverkehr`, `NähereInformationen`, `SchönbrunnerSchloßbrücke`). This appears to stem from how the official OGD City of Vienna payload provides the descriptions.
**Proposed Solution:** Implement a regex-based text sanitization step (e.g., `r'([a-zß])([A-Z])' -> r'\1 \2'`) within the provider ingestion pipeline to automatically insert spaces between lower-case and upper-case letters where appropriate.

### 2. Double-Escaped Ampersands in XML
**Affected Component:** `src/build_feed.py` (`_emit_item`)
**Display Issue Description:** In both the German and English XML feeds, the `&` character is double-escaped in the `<description>` tag. For instance, `Wiener Linien GmbH & Co KG` is rendered as `Wiener Linien GmbH &amp;amp; Co KG`. This happens because `desc_text_truncated` is first manually escaped via `html.escape(..., quote=False)` and then passed to `ET.SubElement(item, "description").text`, which automatically applies its own XML escaping.
**Proposed Solution:** Refactor the security countermeasure. Instead of blanket `html.escape()` which catches `&`, either restrict the manual escaping to angle brackets (`<` and `>`), or apply a strict HTML-stripping function on `desc_text_truncated` so it contains no tags, eliminating the need to manually escape it before passing it to `ElementTree`.

### 3. Hardcoded "Minuten" vs "min" Inconsistency
**Affected Component:** `src/feed/stammstrecke.py`
**Display Issue Description:** The `_build_event` function hardcodes the word `Minuten` in its output (e.g., `Durchschnittliche Verspätung von 1.5 Minuten`). This conflicts with the project's visual harmony guidelines which dictate the use of the abbreviation `min` for delay durations in statistics tables and dashboard outputs.
**Proposed Solution:** Update the string formatting in `src/feed/stammstrecke.py` to use `min` instead of `Minuten` (e.g., `Durchschnittliche Verspätung von 1.5 min`).
