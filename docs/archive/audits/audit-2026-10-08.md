## Audit Update 14:10

### Affected Component
Backend (Translation & Formatting Pipeline: `src/providers/wl_text.py`)

### Display Issue Description
The disruption feed titles occasionally contain redundant dates starting with "am" (e.g., `1/1A/2/3A/57A/71/D: Demonstration am 09.10.2026` as seen in `cache/wl_9d709a/events.json` becoming `1/1A/2/2A/3A/4A/57A/71/D: Demonstration am 09.10.2026, 10.10.2026` in the feed). The `_AB_DATE_RE` regex in `src/providers/wl_text.py` strictly strips dates starting with "ab" (e.g., `Bauarbeiten ab 14.09.2026`), but fails to capture and strip dates starting with "am". This leaves clumsy, redundant phrasing in titles since the validity window is already presented via the item's `starts_at` / `ends_at` tags.

### Proposed Solution
Modify the `_AB_DATE_RE` regex pattern in `src/providers/wl_text.py` from `(?:ab)` to `(?:ab|am)` to ensure both date prefixes are properly sanitized from Wiener Linien feed titles.

### Affected Component
Backend Output Generators (`src/feed/stammstrecke.py`, `scripts/generate_markdown_stats.py`)

### Display Issue Description
According to project memory and frontend string usage, the abbreviation "min" must be used consistently instead of the full word "Minuten" for delay durations in statistics tables and dashboard outputs to maintain visual harmony. However, `scripts/generate_markdown_stats.py` still outputs "Minuten" in markdown headers (e.g., `### Verspätungen ⌀ Minuten je Wochentag` and `### Verspätungen ⌀ Minuten je Stunde`). Additionally, while the frontend strings in `docs/assets/site.js` use the `>` operator correctly, it still retains legacy comments using `≥ 9 Minuten` and `// 5 Minuten`.

### Proposed Solution
Update `scripts/generate_markdown_stats.py` to use "min" instead of "Minuten" in section headers (e.g., change to `### Verspätungen ⌀ min je Wochentag`). Update legacy comments in `docs/assets/site.js` to strictly use the "min" abbreviation and the ">" symbol as per the backend logical checks (e.g. `> 9 min`), avoiding logical mismatches in codebase documentation.
