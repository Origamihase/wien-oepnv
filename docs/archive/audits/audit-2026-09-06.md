# Daily Diagnostic Audit: Wien-ÖPNV Feed & Statistics

_Date: 2026-09-06_

## Audit Update 14:00

### Issue 1: Bare Index Entity Placeholder Leaks in English Feed

**Affected Component**
English RSS Feed (`docs/feed.en.xml`) / Entity Masking Logic (`src/build_feed.py`)

**Display Issue Description**
The MarianMT model translates entity placeholders but mangles them by dropping the `XENT` or `XGLO` prefix and nonce. This leaves bare index leaks in the translated feed, for instance `X4X` in the S 60 ÖBB item: `<title><![CDATA[S 60: Wien Meidling ↔ Wien Hauptbahnhof ↔X4X Wien Stadlau]]></title>`. The regex `_RESIDUAL_PLACEHOLDER_RE` fails to catch these bare indices, resulting in unreplaced placeholders leaking into the public feeds.

**Proposed Solution**
Update the `_RESIDUAL_PLACEHOLDER_RE` in `src/build_feed.py` to correctly identify and flag these bare index placeholders (e.g., `X\d+X`) that the translation model mangled.

### Issue 2: Inconsistent "Minuten" vs "min" wording in Dashboard Stats

**Affected Component**
Markdown Statistics Dashboard (`docs/statistik.md` and `scripts/generate_markdown_stats.py`)

**Display Issue Description**
There is an inconsistency in the use of "Minuten" and "min" for delays in the markdown statistics tables. The "Kennzahlen auf einen Blick" table uses "min" (e.g., `Verspätungen > 9 min (2026)` and `⌀ Verspätung (2026) 1.1 min`), while the breakdown headers use "Minuten" (e.g., `### Verspätungen ⌀ Minuten je Wochentag`). The memories explicitly dictate the use of 'min' instead of 'Minuten' to maintain visual harmony.

**Proposed Solution**
Update `scripts/generate_markdown_stats.py` to replace occurrences of "Minuten" with "min" in the generated markdown table headers.

### Issue 3: Clumsy/Awkward Translations

**Affected Component**
English RSS Feed (`docs/feed.en.xml`) / NMT Translation

**Display Issue Description**
The NMT outputs include some clumsy or literal phrasing that affects readability:
- "Straßenfest" was awkwardly translated as "maintenance of the road fence" in the line 40/41 Währinger Straßenfest item.
- German time formats like "04:30 Uhr" were translated clumsily to "04:30 Clock".

**Proposed Solution**
Use the `_apply_domain_glossary` logic to add robust manual mappings for common terms like "Straßenfest" and "Uhr" to prevent the model from generating these clumsy translations.

### Issue 4: Awkward Truncation of Long Descriptions

**Affected Component**
English/German RSS Feeds (`docs/feed.xml`, `docs/feed.en.xml`) / Description Truncation (`src/build_feed.py`)

**Display Issue Description**
Long text descriptions in the feed items are truncated awkwardly, sometimes completely cutting off the actual reason or important context while keeping long boilerplate text. For instance, in the Zentralfriedhof item, the description ends with `Reason …` (`Grund: …` in German), cutting off the crucial information on why the disruption is happening.

**Proposed Solution**
Improve the `_truncate_summary_180` function in `src/build_feed.py` to prioritize semantic content or implement smarter truncation rules that ensure critical details (like the reason or alternatives) aren't omitted before appending the ellipsis.
