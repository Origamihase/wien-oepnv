# Audit Report - 2026-09-14

## Audit Update 14:30

### Affected Component
Frontend / UI Consistency & Markdown Generator (`docs/assets/site.js`, `src/feed/stammstrecke.py`, `scripts/generate_markdown_stats.py`)

### Display Issue Description
There are wording inconsistencies regarding the display of delays. In `docs/assets/site.js`, the label is `"sub-over-9": "≥ 9 Minuten"`, while `scripts/generate_markdown_stats.py` uses `Kritische Verspätungen (> 9 min)`. Additionally, `src/feed/stammstrecke.py` hardcodes `Minuten` (e.g. `f"{_format_minutes(avg_delay_minutes)} Minuten "`). Project guidelines specify the consistent use of the abbreviation `min` instead of `Minuten`, and logical comparisons (`> 9` instead of `>= 9`).

### Proposed Solution
Modify `docs/assets/site.js` to change `≥ 9 Minuten` to `> 9 min`.
Update `src/feed/stammstrecke.py` to use `min` instead of `Minuten` in strings (e.g., `f"{_format_minutes(avg_delay_minutes)} min "`).
Update `scripts/generate_markdown_stats.py` to change markdown table headings from `### Verspätungen ⌀ Minuten je Wochentag` to `### Verspätungen ⌀ min je Wochentag` and similarly for `je Stunde`.

### Affected Component
Backend (Translation Pipeline `src/build_feed.py` and `docs/feed.en.xml`)

### Display Issue Description
In `docs/feed.en.xml`, the phrase `Fahrtbehinderung` translates clumsily in some contexts (e.g., "After an service obstruction"). Furthermore, phrases such as "Ersatzbus hält", "Züge halten", "Veranstaltung", and "Betrieb ab" appear in feed titles with mixed or incomplete translation logic (for instance, "25: Trains stop Donaufelder Straße 175-177" translates "Züge halten" but sometimes fails when prefixed, and "Line 26E stops Donaufelder road 148" translates "Straße" to "road" because of the lack of proper noun protection or mistranslation of German sentences vs prefixes). Specifically, "Ersatzbus hält" is left untranslated or awkwardly translated in compound items like "Replacement bus stops Karl-Waldbrunner-Platz in front of Schloßhofer Straße".

### Proposed Solution
Change `"Fahrtbehinderung": "service obstruction"` to `"Fahrtbehinderung": "obstruction"` in `_GLOSSARY_BASE` within `src/build_feed.py` to fix the English article mismatch.
Add domain terms `"Veranstaltung": "event"`, `"Betrieb ab": "operation from"`, `"Züge halten": "trains stop"`, and `"Ersatzbus hält": "replacement bus stops"` to `_GLOSSARY_BASE` in `src/build_feed.py` so they are correctly substituted via XGLO prior to neural machine translation.

### Affected Component
Backend (Baustellen Data Source `src/providers/baustellen.py` / `scripts/update_baustellen_cache.py`)

### Display Issue Description
The official OGD City of Vienna payload for Baustellen outputs text with awkwardly concatenated sentences and compound words lacking spaces. For example, `DerFußgängerverkehr` and `NähereInformationen` are emitted verbatim in the payload because the parser does not enforce spacing sanitization, which appears as a display error in the feeds.

### Proposed Solution
Add explicit regex spacing sanitization in `_format_description` in `scripts/update_baustellen_cache.py`. A pattern such as `re.sub(r'([a-z])([A-Z])', r'\1 \2', text)` should be applied to the parsed text strings to insert spaces between improperly concatenated lowercase/uppercase boundaries.
