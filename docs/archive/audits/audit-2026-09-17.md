## Audit Update 16:30

### 1. Affected Component
Translation Pipeline (`src/build_feed.py` and MarianMT model) / Feed Output (`docs/feed.en.xml`)

### Display Issue Description
The raw Wiener Linien payload contains the phrase "Wegen eines Erntedankfestes werden die Linien 27A, 28A und 29A umgeleitet." The translation model (`docs/feed.en.xml`, GUID `5b40951...`) renders "Erntedankfestes" as "Thanksgiving", resulting in the confusing phrase: "Due to Thanksgiving, the lines 27A, 28A and 29A are redirected." This is a localization mismatch since Thanksgiving is an American/Canadian holiday, whereas a generic "harvest festival" or "event" (as seen in the title "Event at 27.09.2026") would be more appropriate for Vienna.

### Proposed Solution
Extend the domain glossary `_GLOSSARY_BASE` in `src/build_feed.py` to explicitly map `Erntedankfest` and `Erntedankfestes` to `harvest festival` or simply `event`, protecting it from the translation model's culturally-biased rendering.

### 2. Affected Component
Translation Pipeline (`docs/feed.en.xml`) / Title and Description Processing

### Display Issue Description
The English description for the U4 disruption (GUID `35a2bf6...`) shows an awkward truncation: `Due to the renovation of the tunnel ceiling of the U4 path or the necessary preparatory work in the road area as well as the repair of shafts by the Vienna … [01.02.2026 – 30.11.2026]`. The original German source states "durch die Wiener Netze - Bereich Fernwärme". The English feed truncates right at "by the Vienna …", dropping the remainder of the entity or the sentence.

### Proposed Solution
Investigate whether the `Wiener Netze` entity is being improperly masked by `_BRAND_ENTITIES` (which might only protect "Wiener Linien", "Wiener Lokalbahnen", etc., but not "Wiener Netze") causing the translation model to truncate at an unrecognized abbreviation/dash, or if the source text itself was truncated. Add `Wiener Netze` to the `_BRAND_ENTITIES` list if it prevents the truncation.

### 3. Affected Component
Title Deduping Logic (`src/providers/wl_lines.py`) / Feed Output (`docs/feed.xml` and `docs/feed.en.xml`)

### Display Issue Description
For the disruption on lines 4A, 80A, and N29 (GUID `5af5bfa564...`), the feed output displays a redundant line prefix in the title: `4A/80A/N29: 4A. 80A, N29: Wittelsbachstraße`. The function `_strip_redundant_line_token` correctly extracts the canonical prefix `4A/80A/N29:`, but fails to strip the secondary list `4A. 80A, N29:` from the body of the title because the regex pattern expects separators like commas and slashes, but the raw data uses a period (`4A.`) which is not matched and stripped.

### Proposed Solution
Update `_strip_redundant_line_token` or `LINES_COMPLEX_PREFIX_RE` in `src/providers/wl_lines.py` to handle periods (`.`) as valid separator characters when attempting to match and strip redundant line prefixes at the start of the title body.
