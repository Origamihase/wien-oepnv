## Audit Update 14:12

**Affected Component:** Feed Generation (`docs/feed.xml` and `docs/feed.en.xml`) & Wiener Linien Cache (`cache/wl_9d709a/events.json`)

**Display Issue Description:**
The feed generator is creating awkward and poorly concatenated title and description texts for Wiener Linien disruptions.
- Missing spaces and formatting issues in descriptions. For example, "Bauarbeiten\nEinstieg bei Vorgartenstraße vor Meiereistraße" becomes "BauarbeitenEinstieg bei Vorgartenstraße vor Meiereistraße" when rendered, or displays clumsily in the feed as `11A: Einstieg bei Vorgartenstraße vor Meiereistraße`.
- Unescaped XML entities (`&lt;`) in descriptions. E.g., `ÖBB-Ersatzbus für &lt;80` appears in `docs/feed.xml` and `docs/feed.en.xml` causing double-escaped entities `&amp;lt;80` in the `<description>` field and `&lt;80` in the `<content:encoded>` field.
- The English feed retains awkward German phrasing due to incorrect or missing translation masks. For example, "D: Züge halten bei Linie O" is translated to "D: Trains stop at line O", and "11A: Einstieg for Vorgartenstraße before Meiereistraße" where "Einstieg" was missed in translation.

**Proposed Solution:**
- Enhance the translation glossary/masks in `src/build_feed.py` (and specifically `_STREET_SUFFIX_RE` and `_mask_entities` logic) to properly catch and format terms like "Einstieg" or "Züge halten bei". Ensure proper spacing/newlines are replaced or preserved during text cleaning.
- Fix XML escaping logic in `src/build_feed.py` or the template builder to decode HTML entities (like `&lt;`) from the raw cache before embedding them into the XML feeds.

**Affected Component:** Frontend UI (`docs/assets/site.js`) vs Backend Generators (`scripts/generate_markdown_stats.py`)

**Display Issue Description:**
- Inconsistent display labels for critical delays. The frontend UI uses `≥ 9 Minuten` in `docs/assets/site.js` (key `"sub-over-9"`), while the backend logic in `scripts/generate_markdown_stats.py` displays `Kritische Verspätungen (> 9 min)` and the underlying logic checks `delay_minutes > DELAY_THRESHOLD_MINUTES`. This is a logical mismatch between displaying "greater than or equal to" (≥) and checking for strictly "greater than" (>).
- Hardcoded wording inconsistency: `docs/assets/site.js` uses `≥ 9 Minuten` (with "Minuten"), but the backend scripts (`scripts/generate_markdown_stats.py`) strictly use `min` (e.g. `Kritische Verspätungen (> {threshold_label} min)`).

**Proposed Solution:**
- Update `docs/assets/site.js` translations for `"sub-over-9"` to use `> 9 min` for consistency with the backend logic (strictly greater than) and abbreviation (`min`).
