# Daily Diagnostic Audit

## Audit Update 14:22

### 1. Affected Component
Frontend String Definitions & Markdown Generation (Consistency)

### Display Issue Description
There is a hardcoded wording inconsistency and abbreviation mismatch across the project regarding the display of delays.
- In `scripts/generate_markdown_stats.py`, the headers use the word "Minuten" (e.g., `### Verspätungen ⌀ Minuten je Wochentag`, `### Verspätungen ⌀ Minuten je Stunde`, `> _Letzte 60 Minuten – automatisch aktualisiert..._`). Memory guidelines state that in statistics tables and dashboard outputs, the abbreviation "min" must be used consistently for visual harmony.
- In `docs/assets/site.js`, the comment and potential frontend logic reference `>= 9 Minuten` instead of using strict `> {DELAY_THRESHOLD_MIN} min`, which contradicts backend logic (the backend uses strict greater-than evaluation `obs.delay_minutes > DELAY_THRESHOLD_MINUTES`).

### Proposed Solution
- Update `scripts/generate_markdown_stats.py` to replace "Minuten" with "min" in section headers and automated workflow footers.
- Ensure the frontend string definitions strictly use the strict greater-than logic `> {DELAY_THRESHOLD_MIN} min` rather than `>= 9 Minuten`.

### 2. Affected Component
Sanitization / Text Clean-up (Glued Word Repair)

### Display Issue Description
The raw data from the official OGD City of Vienna payload for Baustellen (`cache/baustellen_d438c3/events.json`) contains descriptions with awkwardly concatenated words such as `DieHaltestelle`, `DerFußgängerverkehr`, and `NähereInformationen`. As noted in the memory: "The regex spacing sanitization in `src/utils/text.py` (`_GLUED_WORD_RE`) inserts spaces based on a strict list of allowed opening function words (e.g., `Im`, `Am`), but it can miss standard German articles like `Der` and `Die`, leaving some terms glued." Checking `docs/feed.xml`, I found these exact errors persisting (e.g., `DieHaltestelle`, `DerFußgänger- und Radverkehr`).

### Proposed Solution
Update `_GLUED_WORD_RE` in `src/utils/text.py` to include `Der` and `Die` in the whitelist of opening function words that allow a space insertion when followed by an uppercase letter without a preceding space, so that phrases like `DieHaltestelle` correctly become `Die Haltestelle`.

### 3. Affected Component
Feed Pipeline (HTML to Plaintext conversion)

### Display Issue Description
The HTML-to-plaintext conversion logic in `src/utils/text.py`'s `html_to_text` function fails to properly insert spaces between block-level tags when parsing strings such as `<h2>Bahnsteigsanierung</h2> <p>Wegen...`. As mentioned in memory, this results in sentences being awkwardly glued together (e.g., 'Bahnsteigsanierung Wegen').

### Proposed Solution
Modify the HTML-to-Plaintext logic in `_HTMLToTextParser` or the cleanup regex in `html_to_text` to ensure that consecutive block tags correctly separate text with spaces or newlines instead of concatenating them, preventing cases like "Bahnsteigsanierung Wegen".

### 4. Affected Component
Translation Escaping (MarianMT)

### Display Issue Description
The English translation pipeline `src/build_feed.py` and downstream translation handling correctly attempts to substitute placeholders for translation (e.g., `XENT`), but due to MarianMT model bugs, it may mangle placeholders by dropping the prefix, leaving bare indices like `X4X`. This is explicitly listed as a known display bug in memory.

### Proposed Solution
Update `_RESIDUAL_PLACEHOLDER_RE` in `src/build_feed.py` to account for bare index leaks from the MarianMT model.

### 5. Affected Component
Feed Translation (Double Escaping)

### Display Issue Description
In `src/build_feed.py`, manually escaping ampersands using `html.escape` inside XML tags can result in double-escaped entities (e.g., `&amp;amp;`) in plaintext `<description>` tags, as downstream tools like `xml.etree.ElementTree` subsequently re-escape the already escaped text.

### Proposed Solution
Remove the redundant `html.escape` call in `src/build_feed.py` when preparing text for the XML `<description>` tag, allowing `xml.etree.ElementTree` to handle the escaping.

### 6. Affected Component
Translation Glossary (English Feed)

### Display Issue Description
Stop relocation descriptions and other disruption announcements often contain German prefix fragments (e.g., 'etwa 20 Meter in Richtung', 'Ab', 'Ersatzlos') that the MarianMT model may leave untranslated. Also, common transit nouns like 'Einstieg' must be mapped in the domain glossary (`_apply_domain_glossary`) to be substituted via `XGLO` placeholders.

### Proposed Solution
Explicitly preprocess these fragments or map them in the translation glossary (`src/build_feed.py`) to prevent mixed-language output in the English feed. Add 'Einstieg' to the glossary.
