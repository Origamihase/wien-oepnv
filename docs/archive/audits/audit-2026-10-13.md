## Audit Update 14:21

### Affected Component
`scripts/generate_markdown_stats.py`

### Display Issue Description
The Markdown statistics table headers generated by the script use the full word "Minuten" (e.g., `### Verspätungen ⌀ Minuten je Wochentag` and `### Verspätungen ⌀ Minuten je Stunde`). This violates the project guideline to consistently use the abbreviation "min" in statistics tables and dashboard outputs for visual harmony.

### Proposed Solution
Update `scripts/generate_markdown_stats.py` to replace the hardcoded "Minuten" with "min" in the header strings (e.g., `### Verspätungen ⌀ min je Wochentag` and `### Verspätungen ⌀ min je Stunde`).

### Affected Component
`docs/feed.en.xml` and `src/build_feed.py` (Translation Glossary)

### Display Issue Description
The phrase "kann die Haltestelle ... nicht einhalten" is translated clumsily by the MarianMT model as "cannot follow the stop" (e.g., "Line 66A cannot follow the stop Atzgersdorf, Kirchenplatz towards Reumannplatz."). This is an unnatural phrasing in English for transit operations.

### Proposed Solution
Add a rule to the domain glossary in `src/build_feed.py` (or related translation mapping module) to map "kann die Haltestelle [X] nicht einhalten" to an appropriate idiom such as "cannot serve the stop [X]" using `XGLO` placeholders prior to Neural Machine Translation.

### Affected Component
`src/build_feed.py` (Summary Truncation Logic)

### Display Issue Description
Critical routing details are being dropped from the summary descriptions in the feed due to aggressive sentence extraction and truncation. For example:
- The combined event `1/71/D: Demonstration` is summarized generically as "Wegen einer Demonstration kommt es zu einer Einschränkung des öffentlichen Verkehrs." and the actual line diversions are missing.
- The event `D: Fremder Verkehrsunfall` had its diversion details dropped or obscured in combined events.
The `_truncate_summary_180` logic and the sentence splitting logic prioritize the first sentence, which in many cases is a generic boilerplate phrase, causing multi-line disruption descriptions to lose critical re-routing information for the lines mentioned in subsequent sentences.

### Proposed Solution
Refine the sentence extraction logic in `_format_item_content` (and related helpers) to detect and bypass generic preamble sentences (e.g., "Wegen einer Demonstration kommt es zu Einschränkungen..."), prioritizing the inclusion of actual measure blocks and re-routing consequences within the 180-character budget.

### Affected Component
`src/providers/wl_text.py` (Title Sanitization)

### Display Issue Description
Redundant date strings are left in the feed titles when they start with "am". For instance, the feed outputs the title `1/71/D: Demonstration am 13.10.2026`. The memory notes that the `_AB_DATE_RE` regex strips dates starting with "ab", but fails to match dates starting with "am", stranding these dates in the titles.

### Proposed Solution
Extend the date-stripping regex (e.g., `_AB_DATE_RE` or a related regex) in `src/providers/wl_text.py` to match dates starting with "am" (e.g., `am DD.MM.[YYYY]`) in addition to "ab", ensuring redundant dates are consistently removed from the feed titles.
