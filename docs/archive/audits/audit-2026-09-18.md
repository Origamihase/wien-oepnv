# Audit Update 2026-09-18

## Affected Component
`docs/feed.xml` / `docs/feed.en.xml` (Translation Pipeline & Text Presentation)

## Display Issue Description
1. **Missing Redirecting Station in Translation**: In the English feed for "12/2: Veranstaltung", the phrase "Die Züge werden weiter zum Karlsplatz umgeleitet" is translated as "Trains are redirected to the Karlsplatz." The article "the" is awkward and should be removed.
2. **Grammar Mismatch**: For the switch fault on Tullnerfeld, the English feed states: "Due to an switch fault". "switch" begins with a consonant sound, so it should be "a switch fault".
3. **Awkward Phrasing**: For the "12A: Verunreinigung" event, the title translates as "12A: Impurity", but the description translates as "Reason: contamination." There is a mismatch.
4. **HTML in Description**: In the DE cache for "72A: Kraftwerk Simmering", the description contains raw HTML (`<p>`, `<span>`, `<strong>`, etc.). In the DE feed, these are seemingly stripped or escaped, but the text runs together awkwardly without spacing, such as "Haltestellenverlegung der Linie 72A in Richtung Hasenleitengasse Haltestelle: Kraftwerk Simmering Von: 1. Haidequerstraße 2 Nach: 1. Haidequerstraße 510 Dauer: Ab …"
5. **Bold text leak**: In the OEBB cache for Tullnerfeld, there's `<b>waren</b>` and `<br>`. These get stripped but maybe we lose formatting or space. In the feed: "Wegen einer Weichenstörung waren zwischen Tullnerfeld Bahnhof und Wien Meidling Bahnhof (U) bis 15:43 Uhr nur eingeschränkt Fahrten möglich."
6. **Formatting Inconsistencies**: There is inconsistent abbreviation of "Minuten" to "min" across statistics tables in `docs/statistik.md` and `README.md` (e.g., "Verspätungen ⌀ Minuten je Wochentag"). The frontend string definitions in `docs/assets/site.js` use the labels "≥" but logic strictly checks `>`.

## Proposed Solution
- **Translation / Glossary fixes**: Update `src/build_feed.py`'s `_GLOSSARY_BASE` or post-translation cleanup to handle "switch fault" starting with a consonant (e.g. check if the model inserts "an " and correct it, or change the phonetic starting sound mapping if applicable). Add "Verunreinigung" to the glossary consistently as "contamination".
- **HTML stripping**: Update HTML-stripping logic in the feed builder or WL provider (e.g., `src/providers/wl_linien.py` or similar) to replace block-level tags like `<p>` and `<br>` with spaces or newlines instead of completely omitting them, which runs words together.
- **Frontend / Stat Formatting**: Update labels in `docs/assets/site.js` to align with the actual condition (`>`). Standardize the abbreviation "min" in `scripts/generate_markdown_stats.py` instead of using "Minuten".

## Audit Update 19:08 — Korrektur von Befunden (2026-09-17 und dieser Datei)

Nachgemessen bei der Umsetzung. Drei Befunde halten der Prüfung nicht stand;
sie stehen hier richtiggestellt, damit niemand nach der alten Fassung handelt.
Die Ursprungsbefunde bleiben unverändert stehen — ein datiertes Audit ist ein
Protokoll.

### D.2 (Audit 2026-09-17) — in Mechanismus **und** Größe falsch

Der Befund las `naming_issues: 0` gegen acht Namenskollisionen und schloss:
*„Die Duplikatprüfung arbeitet weiterhin koordinatenbasiert"*, mit der
Empfehlung, alle acht zu melden (*„Erwartetes Ergebnis beim ersten Lauf: 8"*)
und hinter eine Allowlist zu legen.

**Falsch beim Mechanismus.** `_find_alias_collision_issues` gruppiert alle
acht bereits als konkurrierende Claimants. Es schweigt nach seinem eigenen,
dokumentierten Kontrakt: die Claimants sind sich über `in_vienna` einig und
liegen 157–479 m auseinander. Die 0 war eine korrekte Antwort auf die Frage,
die dieser Check stellt.

**Falsch bei der Größe.** Sieben der acht sind keine Defekte. Wien betreibt
verschiedene Haltestellen unter einem Namen — `Märzstraße` zweimal, 479 m
auseinander — und in diesen sieben Gruppen trägt **jedes** Mitglied einen
`wl_stops`-Eintrag des gemeinsamen Namens; der Nachschlag landet also auf
einer Haltestelle des richtigen Namens, egal wer gewinnt.

**Warum die Empfehlung schadet.** Alle acht zu melden heißt, das am
2026-05-12 bewusst entfernte Namens-Eindeutigkeitsgate wiederherzustellen —
jenes, das die DIVA-Suffixe in den Feed zwang und einmal 30 Namensbefunde zu
1759 quarantänisierten WL-Einträgen auffächerte (siehe `_format_identifier`).

**Was tatsächlich zutrifft:** genau **ein** Eintrag löst falsch auf.
`Wien Heizwerkstraße (WL)` / `wl_diva 60200228` trägt zwei Haltestellen namens
`Deutschstraße` und gewinnt den Schlüssel gegen `wl_diva 60201742`, dessen
Haltestellen *Heizwerkstraße* heißen. Das taugliche Prädikat ist deshalb nicht
Namenseindeutigkeit, sondern: *der Eintrag, der den Namen gewinnt, trägt ihn
nicht, ein Geschwistereintrag aber schon.* 1 Treffer live, 0 auf den anderen
sieben Gruppen, 0 auf den 105 Einträgen ohne Haltestelle eigenen Namens.

Umgesetzt als `name_ownership_issues` (PR #1827). Bewusst **nicht** an den
Quarantäne-Pfad gehängt: der löscht den beanstandeten Eintrag und nähme dem
Verzeichnis damit seine einzigen `Deutschstraße`-Haltestellen.

### D.1 (Audit 2026-09-17) — Empfehlung für sieben der acht Paare falsch

D.1 empfiehlt, *„die acht Paare zusammenzuführen"* oder zu disambiguieren, mit
Zusammenführen als Vorzugsvariante. Nach obiger Messung gilt das für **ein**
Paar (Heizwerkstraße/Deutschstraße), und dort ist es eine Umbenennung, kein
Merge. Die anderen sieben sind legitime, verschiedene Haltestellen; sie
zusammenzuführen würde Daten zerstören, nicht bereinigen.

D.1 bleibt offen — reduziert auf diesen einen Fall.

### Punkt 4 dieser Datei (HTML-Stripping) — für die veröffentlichte Ausgabe widerlegt

Der Befund beschreibt zusammengeklebte Wörter durch entferntes HTML. Das
Phänomen ist real — in **32 %** der Cache-Beschreibungen — und erreicht
**null von 314** veröffentlichten Texten. Nachgewiesen, indem eine verklebte
Cache-Beschreibung durch `_format_item_content` geschickt wurde:

```
Cache    : DerFußgängerverkehr kann aufrecht gehalten werden.Nähere …
Gerendert: Der Fußgängerverkehr kann aufrecht gehalten werden.
```

Die Pipeline trennt bereits korrekt. **Kein Handlungsbedarf.** Der Befund
beschreibt den Cache, nicht das Ergebnis — derselbe Fehlertyp wie bei D.2.
