### S.1 — `transformers` schreibt Code aus dem Modell-Repository in den Cache (Sicherheit) — bewertet, Ausnahme mit Begründung

| | |
| --- | --- |
| **Betroffene Komponente** | `transformers` (`requirements.txt`: `>=4.41,<5`, in der CI 4.57.6); `src/build_feed.py`, `_get_translation_pipeline`; `scripts/run_static_checks.py`, `_TRANSFORMERS_IGNORED_VULNS` |
| **Problembeschreibung** | Laut Meldung sind die Versionen 4.49.0 bis 5.8.1 betroffen; eine korrigierte Version gab es am 01.10. nicht. `GenerativePreTrainedModel.load_custom_generate()` lädt `custom_generate/generate.py` aus einem Modell-Repository in `~/.cache/huggingface/modules`, bevor `trust_remote_code` geprüft wird. Ausgeführt wird die Datei nicht, aber sie bleibt liegen. <br>Anders als bei den 13 bisher ausgenommenen Meldungen läuft dieser Pfad bei uns mit. `from_pretrained` ruft `load_custom_generate()` bei **jedem** Laden auf (`modeling_utils.py`, 4.57.6), also auch für unser einziges Modell `Helsinki-NLP/opus-mt-de-en`. <br>Ein Schaden setzt voraus, dass genau dieses Repository kompromittiert wird und die Datei erhält. Dann landet sie im Cache `~/.cache/huggingface`. Den reichen `build-feed.yml`, `update-cycle.yml` und `manual-full-refresh.yml` über `actions/cache` einen Monat lang weiter. Ausgeführt würde sie nur mit `trust_remote_code=True`, das das Projekt nie setzt. Die Modell-Revision ist bisher nicht festgelegt; jeder Push in das Repository erreicht den Build. |
| **Konkreter Lösungsvorschlag — umgesetzt (Schritt 1)** | Die Meldung steht in `_TRANSFORMERS_IGNORED_VULNS`, mit eigener Begründung im Kommentar. Der Kommentar sagte bisher, alle Einträge beträfen nicht genutzte Funktionen; das ist korrigiert. <br>Die Logzeile beim Laden nennt den Commit der geladenen Revision (`_model_revision`, aus `model.config._commit_hash`). <br>`pip-audit` mit der neuen Liste: Exit 0, 9 Meldungen ausgenommen. |
| **Konkreter Lösungsvorschlag — offen (Schritt 2)** | Das Modell auf den geloggten Commit festlegen (`revision=` beim Laden). Danach erreicht keine spätere Änderung am Repository den Build mehr, auch über diese Meldung hinaus. Aus der Sandbox ist Hugging Face nicht erreichbar, und einen falschen Commit festzulegen hieße, dass kein Modell lädt und der EN-Feed deutsch bleibt. Deshalb kommt der Commit aus dem Log des nächsten Feed-Laufs. <br>Ein Downgrade auf `<4.49` wäre möglich. Er brächte aber ältere Versionen mit eigenen Meldungen zurück und könnte die Übersetzungen verändern; nicht empfohlen. <br>Neu bewerten, sobald `transformers` eine korrigierte Version veröffentlicht. |
