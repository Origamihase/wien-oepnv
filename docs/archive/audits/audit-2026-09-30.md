## Audit Update 16:30

### Affected Component
Translation Pipeline (`src/build_feed.py` / `_RESIDUAL_PLACEHOLDER_RE`)

### Display Issue Description
The English feed contains mangled residual placeholders where the neural machine translation model has dropped the `XGLO` or `XENT` prefix and nonce, leaving only the bare numeric index and trailing `X` attached to the preceding word. Examples from `docs/feed.en.xml`:
- "Wien Franz-Josefs-Bahnhof0X"
- "service obstruction0X"
The current `_RESIDUAL_PLACEHOLDER_RE` guard fails to catch these leaks because it expects bare indices to be wrapped in `X` on both sides (`X\d{1,3}X`) and not adjacent to alphanumeric characters (`(?<![A-Za-z0-9])`). When the model drops the leading `X` of the index chunk, or drops the entire `XGLO<nonce>X` prefix, leaving just `0X` (e.g. `<index>X`) glued to the word, the pattern fails to match.

### Proposed Solution
The scope of this audit is strictly read-only. However, to fix this issue in a code modification task, `_RESIDUAL_PLACEHOLDER_RE` should be expanded to detect these bare `<index>X` fragments even when glued to alphanumeric characters (e.g., adding a pattern for `\d{1,3}X(?![A-Za-z0-9])` at the end of a word, or adjusting the lookbehind of the bare index regex).

## Audit Update 16:55

### Affected Component
Title Deduplication & Extraction (`src/providers/wl_lines.py` / `LINE_PREFIX_STRIP_RE`, `LINES_COMPLEX_PREFIX_RE`)

### Display Issue Description
The regexes designed to extract and strip line prefixes (`LINE_PREFIX_STRIP_RE` and `LINES_COMPLEX_PREFIX_RE`) require a trailing colon (`:`) to match. This fails to account for titles where the prefix uses mixed delimiters, periods, or has no colon, leaving duplicate line codes stranded in the body of the feed item title.
Examples from the memory context indicate these fragments are left in titles:
- `3A: 3A...`
- `Linien 25 und 26`
- `4A. 80A, N29:`

Because the stripping mechanism in `_extract_prefix_lines` relies on matching these strict regexes, anything lacking a strict colon suffix (or having internal dots like `4A. 80A`) escapes the prefix extraction and remains as redundant duplication in the text body.

### Proposed Solution
Modify `LINES_COMPLEX_PREFIX_RE` and `LINE_PREFIX_STRIP_RE` to be more permissive regarding delimiters and punctuation.
- Allow optional periods and mixed comma/period separation (e.g., `4A. 80A, N29:`).
- Specifically for the word "Linien", allow matching the phrase "Linien X und Y" even when not followed by a colon.
- Update `_extract_prefix_lines` logic to correctly split on periods when extracting these relaxed matches.
This audit strictly observes read-only limitations; actual code changes should be deferred to a separate implementation task.
