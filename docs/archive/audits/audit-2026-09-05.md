# Audit Report - 2026-09-05

This is an automated audit report documenting recent diagnostic findings regarding UI and logic inconsistencies.

## 1. Logic & Display Mismatch

**Affected files:**
- `docs/assets/site.js`
- `docs/assets/site.min.js`
- `scripts/generate_markdown_stats.py`
- `src/feed/stammstrecke.py`

**Problem:**
The frontend and generated markdown display text labels indicating "≥ 9 Minuten" or "Verspätungen > 9 min". However, the actual backend logic checks for strictly greater than 9 minutes (i.e. `delay_minutes > DELAY_THRESHOLD_MINUTES` where `DELAY_THRESHOLD_MINUTES = 9.0`). A delay of exactly 9.0 minutes does not trigger the event. This causes a mismatch between the label "≥ 9" and the actual data logic "> 9".

**Proposed Solution:**
Update the frontend and markdown generation logic labels to correctly reflect the strict inequality (e.g., "> 9 min") to align with the backend filter.


## 2. Wording Inconsistency

**Affected files:**
- `docs/assets/site.js`
- `docs/assets/site.min.js`
- `src/feed/stammstrecke.py`

**Problem:**
The project guidelines and memory specify that the abbreviation "min" must be used consistently instead of the full word "Minuten" for delay durations in statistics tables and dashboard outputs, to maintain visual harmony. However, "Minuten" is currently hardcoded in translation strings (e.g., `sub-over-9`: "≥ 9 Minuten") and in `stammstrecke.py` (e.g., `f"{_format_minutes(avg_delay_minutes)} Minuten "`).

**Proposed Solution:**
Replace all occurrences of "Minuten" with "min" in `docs/assets/site.js` (and subsequently rebuild `site.min.js`), as well as in `src/feed/stammstrecke.py` where appropriate, ensuring consistency across all user-facing output.

## 4. CI Failure: pip-audit identifying transformers vulnerabilities

**Affected files:**
- `scripts/run_static_checks.py`

**Problem:**
The CI suite fails during the `pip-audit` step because four new vulnerabilities (`PYSEC-2026-2288`, `PYSEC-2026-2289`, `PYSEC-2026-2290`, `CVE-2026-9856`) were recently disclosed for the `transformers` library on the `>=4.41,<5` line. ## Daily Audit Update

### 5. Translation Sentinel Leak (X4X)

**Affected Component**
- `src/build_feed.py` (Translation pipeline)
- English Feed (`docs/feed.en.xml`)
- State Cache (`data/first_seen.json`)

**Display Issue Description**
A placeholder sentinel (`X4X`) has leaked into the English feed title for an ÖBB S 60 disruption: `S 60: Wien Meidling ↔ Wien Hauptbahnhof ↔X4X Wien Stadlau`. The NMT model (MarianMT) mangled the `XENT` placeholder by dropping the prefix and nonce entirely during translation, leaving only the bare index `X4X`. The `_RESIDUAL_PLACEHOLDER_RE` regex strictly checks for `(?:XENT|XGLO)[A-Za-z0-9]*X`, which requires the prefix to be present. As a result, it fails to catch this specific corruption, allowing the leaked sentinel to be cached and published to subscribers.

**Proposed Solution**
Enhance the `_RESIDUAL_PLACEHOLDER_RE` regex in `src/build_feed.py` to also catch bare index-like placeholders (e.g., `X\d+X`) that have lost their prefix, so the pipeline can reject and self-heal from these severe NMT corruptions.

### 6. Clumsy Translation / Inconsistent Localization for "Tor"

**Affected Component**
- `src/build_feed.py` (`_STREET_SUFFIX_RE` Entity masking)
- English Feed (`docs/feed.en.xml`)

**Display Issue Description**
There is an inconsistency in how location names containing "Tor" (e.g., "Zentralfriedhof, 3. Tor") are handled. In the English feed, some items translate it as "Gate" (e.g., `Zentralfriedhof, 3. Gate` and `11/71: Zentralfriedhof, 4. Gate`), while others preserve the German "Tor" (e.g., `between Otto-Probst-Platz and Zentralfriedhof, 3. Tor`). Because "Tor" is a proper place suffix in this context but is not shielded by the `_STREET_SUFFIX_RE` entity masker, the NMT model translates it inconsistently, leading to clumsy localized output where proper place names are partially translated.

**Proposed Solution**
Add `[Tt]or` to the `_STREET_SUFFIX_RE` regex in `src/build_feed.py` so that it is properly masked as an entity and preserved verbatim in the English output, matching the robust handling of other proper noun suffixes like Straße, Platz, and Gasse.
