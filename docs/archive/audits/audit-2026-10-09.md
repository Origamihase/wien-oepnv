
## Audit Update 14:15

### Affected Component
Feed Display & Translation (`docs/feed.xml`, `docs/feed.en.xml`)

### Display Issue Description
The English translation of the disruption for line 25 uses a literal and incorrect translation for the word "hält". The German title is "25: Ersatzbus 26E hält Karl-Waldbrunner-Platz vor Schloßhofer Straße", which translates to "25: Replacement bus 26E holds Karl-Waldbrunner-Platz ahead of Schloßhofer Straße" in `docs/feed.en.xml`. The correct English transit idiom is "stops at" rather than "holds". Memory confirms this is a known issue for transit verbs like "Züge halten" or "Busse halten".

### Proposed Solution
Update the translation glossary or preprocessing step in `src/build_feed.py` (`_apply_domain_glossary`) to map "hält" / "halten" to "stops at" / "stop at" when used in the context of transit vehicles (e.g. buses, trains).

### Affected Component
Markdown Statistics & UI (`docs/statistik.md`, `docs/assets/site.js`)

### Display Issue Description
There are wording inconsistencies and potential logic mismatches between the UI and backend logic:
1.  **Wording:** `docs/statistik.md` and `docs/assets/site.js` use the word "Minuten" in headers/comments, while the rest of the statistics tables use the abbreviation "min" (e.g. "Verspätungen > 9 min (2026)", "1.0 min"). Memory guidelines strictly require using "min" for visual harmony.
2.  **Logic mismatch in display labels:** The UI code `docs/assets/site.js` has a comment indicating a tile is labeled "≥ 9 Minuten" (greater than or equal to), while the logic checks `d > DELAY_THRESHOLD_MINUTES`. This mismatch can confuse users about whether exactly 9 minutes is considered a delay threshold. Memory notes confirm the backend uses a strict greater-than evaluation.

### Proposed Solution
1.  Modify `scripts/generate_markdown_stats.py` to use "min" consistently instead of "Minuten" in all generated markdown output.
2.  Update `docs/assets/site.js` to change the hardcoded string "Minuten" to "min" and correct any display labels or comments from "≥" to ">" to accurately reflect the strict greater-than threshold logic.
