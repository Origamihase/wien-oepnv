# Audit Report - 2026-09-22

## Audit Update 14:18
### Affected Component
`scripts/generate_markdown_stats.py` (Dashboard generation)
### Display Issue Description
The Markdown statistics generator uses the full word "Minuten" in multiple table headers, such as "### Verspätungen ⌀ Minuten je Wochentag" and "### Verspätungen ⌀ Minuten je Stunde", as well as in the footer text ("Letzte 60 Minuten"). This violates the project's visual harmony constraint, which dictates the consistent use of the abbreviation "min" for delay durations in all statistics tables and dashboard outputs.
### Proposed Solution
Modify `scripts/generate_markdown_stats.py` to replace "Minuten" with "min" in the table headers and footer texts.

### Affected Component
`src/utils/text.py` (Text processing / Space insertion) & `cache/baustellen_d438c3/events.json`
### Display Issue Description
The raw data for Stadt Wien Baustellen contains awkwardly glued words lacking spaces, such as "DerFußgängerverkehr" and "Außerhalbder". The regex pattern `_GLUED_WORD_RE` in `src/utils/text.py` inserts spaces based on a strict list of allowed opening function words (`Im|Am|An|Um|Ab|In|Zu|Es`), but misses standard German articles like `Der` and `Die`, leaving these terms glued in the output. This results in clumsy phrasing in the generated disruption descriptions.
### Proposed Solution
Expand the `_GLUED_WORD_RE` regex to include definite articles (`Der`, `Die`, `Das`) and other common starters to successfully sanitize glued sentences in descriptions.

### Affected Component
`src/providers/wl_text.py` (Date stripping in Title)
### Display Issue Description
The `_tidy_title_wl` function uses a date-stripping regex (`_AB_DATE_RE`) that strips the string `ab DD.MM.[YYYY]` but its current structure causes two-digit years to occasionally be stranded and glued to the preceding word, for example transforming "Bauarbeiten ab 14.09.26" into "Bauarbeiten26".
### Proposed Solution
Refactor `_AB_DATE_RE` to reliably consume the entire date string (including the 2-digit year) or skip it cleanly without stranding characters.

### Affected Component
`src/build_feed.py` (Translation Pipeline - Entities)
### Display Issue Description
The translation engine uses the `_STREET_SUFFIX_RE` regex to protect proper nouns from translation. However, the pattern can inadvertently capture valid disruption terms containing street-like suffixes, misinterpreting them as proper nouns. Similarly, the English translation output incorrectly includes domain jargon terms like "Einstieg" if not properly mapped to placeholders (`XGLO`) via the domain glossary, resulting in them being masked as untranslatable entities (`XENT`).
### Proposed Solution
Add specific domain vocabulary (e.g., "Einstieg") to the `_apply_domain_glossary` step to ensure it is substituted and correctly translated rather than incorrectly masked. Ensure `_STREET_SUFFIX_RE` strictly matches only proper nouns.
