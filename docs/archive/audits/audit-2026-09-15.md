## Audit Update 14:35

### Affected Component
`docs/feed.en.xml` (Translation Pipeline / MarianMT NMT)

### Display Issue Description
The English translation for disruption items starting with certain numbers/characters is failing because the translation pipeline produces output that retains residual entity or glossary placeholders, which are caught and blocked by the `_cached_translation` and `_translate_text_attempt` guardrails. This causes the feed item to silently fall back to the German source, resulting in untranslated text reaching the subscriber. For example, `79B: Verkehrsunfall` fails to translate because the NMT model's generated output contains a residual placeholder and is correctly blocked. However, this means "Traffic accident" is never shown in the English feed for `79B`.

In addition, the `_STREET_SUFFIX_RE` in `src/build_feed.py` was not protecting words like "Verkehrsunfall", meaning the pipeline's glossary has to manually protect it or else it passes unprotected into the NMT model.

### Proposed Solution
The issue lies with the NMT model (MarianMT) corrupting placeholders or the exact regex format expected not being found. The regular expression checks such as `_RESIDUAL_PLACEHOLDER_RE` in `src/build_feed.py` should be reviewed to ensure they gracefully handle slightly mangled placeholders, or the NMT tokenization/generation parameters should be adjusted. Furthermore, ensure untranslated words are correctly covered in the domain glossary.

## Audit Update 14:38

### Affected Component
Markdown statistics (`docs/statistik.md` and `scripts/generate_markdown_stats.py`)

### Display Issue Description
There is a hardcoded inconsistency where the statistics dashboard (`docs/statistik.md`) outputs "Minuten" in header fields such as `### Verspätungen ⌀ Minuten je Wochentag` but uses "min" in data rows (e.g. `1.1 min`). According to project visual harmony standards in memory, the abbreviation "min" must be used consistently instead of "Minuten" for delay durations across statistics tables and dashboard outputs.

### Proposed Solution
Modify `scripts/generate_markdown_stats.py` to use "min" in all markdown headers (e.g., `### Verspätungen ⌀ min je Wochentag` or `### Verspätungen (⌀ min) je Wochentag`) and re-run the generator to update `docs/statistik.md` so that the visual harmony standard is strictly enforced.
