## Audit Update 14:15

### Affected Component
`docs/feed.en.xml` (Translation Pipeline / MarianMT NMT)

### Display Issue Description
English translation placeholders leak (e.g., `KreuzgasseX` instead of `Kreuzgasse`). Untranslated jargon such as `Bahnhst` leaks into English. Clumsy phrasing such as "to expected 23:59 clock".

### Proposed Solution
Improve glossary replacements (`_apply_domain_glossary`) to handle "Bahnhst", correct residual entity placeholder regexes (`_RESIDUAL_PLACEHOLDER_RE`) in `src/build_feed.py` to prevent `XENT` / `XGLO` mangling.

### Affected Component
`docs/feed.en.xml` and `docs/feed.xml`

### Display Issue Description
Double escaped `<80` causes `&lt;80` inside `<![CDATA[...]]>` blocks and `&amp;lt;80` in standard XML fields.

### Proposed Solution
Stop double-escaping content meant to be inside CDATA, or parse/unescape incoming entities from Wiene Linien safely before writing to XML.

### Affected Component
UI Consistency (`docs/assets/site.js`, `scripts/generate_markdown_stats.py`, and `src/feed/stammstrecke.py`)

### Display Issue Description
The threshold for heavy delays is calculated inconsistently. `docs/assets/site.js` calculates it as `>= 9` (`valid.filter((r) => r.delay >= 9).length;`). However, `scripts/generate_markdown_stats.py` uses `>` (`r.delay_minutes > DELAY_THRESHOLD_MINUTES` where threshold is `9`). Furthermore, `src/feed/stammstrecke.py` and `scripts/generate_markdown_stats.py` output `Minuten` instead of `min` as dictated by visual harmony standards.

### Proposed Solution
Align the JS frontend filter (`>= 9`) with the python backend's threshold (`> 9`), and update python backend output strings to use `min`.
