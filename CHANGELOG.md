# Changelog

Alle nennenswerten Änderungen an diesem Projekt werden dokumentiert. Das Format orientiert sich an
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

Die Einträge stehen in Tagesdateien unter [`changelog/`](changelog/), weil keine Datei mehr als
700 Zeilen haben darf (`docs/architecture.md`, §1, „Höchstens 700 Zeilen je Datei“). In jeder Datei
stehen die neuesten Einträge oben.

**Neuer Eintrag:** oben in `changelog/<JJJJ-MM-TT>.md` des Tages, an dem die Änderung gemacht wurde
(Wiener Datum), mit dem Datum im fett gesetzten Titel. Gibt es die Datei noch nicht, wird sie mit dem
gleichen Kopf wie die anderen angelegt und hier oben in ihrem Monat verlinkt. Hätte eine Tagesdatei
mehr als 700 Zeilen, geht es in `<JJJJ-MM-TT>-2.md` weiter. In diese Datei selbst kommen keine
Einträge (`tests/test_changelog_parts.py`).

**Entscheidung zu Feed-Texten:** Ein Eintrag, der festlegt, wie ein Text im Feed lautet (Wortwahl,
Zeitzeile, Titel, Kürzung, Übersetzung, Reihung, was bleibt und was wegfällt), bekommt im selben Pull
Request seine Zeile unter „Entschieden, also kein Fund“ in `scripts/ki_waechter_prompt.md`, damit der
KI-Wächter die Entscheidung kennt und nicht als Fehler meldet (Betreiberentscheidung 2026-11-05,
`docs/reference/ki_waechter.md`).
